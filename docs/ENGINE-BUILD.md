# Local NTFS engine build

Updated 5 October 2026. This is a development toolchain for disposable, ordinary NTFS image files. It does not enable Finder writes, install a filesystem driver, mount a volume, run a privileged helper, or certify physical-drive use.

## Build

Prerequisites: macOS, Apple's Command Line Tools, HTTPS access to the two source hosts. Run from the repository root as a normal user:

```sh
scripts/engine-build.sh            # Current host architecture
scripts/engine-build.sh x86_64     # Intel
scripts/engine-build.sh arm64      # Apple Silicon, cross-compilation if necessary
```

Everything remains under ignored `.local-engine/`. There is no `sudo`, Homebrew installation, `make install`, launch service, mount, disk-image attachment, or `/dev` target. NTFS-3G's generated `configure` is included in its release archive, so system Automake/Libtool installation is unnecessary. `pkgconf` is compiled locally because the upstream configure script requires it even when the FUSE driver is disabled.

Outputs:

```text
.local-engine/bin/<architecture>/mkntfs
.local-engine/bin/<architecture>/ntfscp
.local-engine/bin/<architecture>/ntfscat
.local-engine/bin/<architecture>/ntfsinfo
.local-engine/bin/<architecture>/ntfsls
.local-engine/bin/<architecture>/licenses/
.local-engine/bin/<architecture>/build-manifest.txt
.local-engine/bin/<architecture>/binary-checksums.txt
.local-engine/logs/ntfs-<architecture>.log
```

The small exported set is for the image test harness. Upstream also builds utilities such as `ntfsfix`, `ntfsresize`, and `ntfsclone` in its retained source tree; Nativol does not expose or run them. These upstream binaries can accept real devices if manually invoked. The application must use a separate guard that accepts only newly created regular test-image files and never forwards a user-chosen device path.

## Configuration and macOS details

The build disables the FUSE mount driver, shared `libntfs-3g`, external plugins, cryptographic extras, mount helpers, and installation-side linker-cache changes. Utilities statically link `libntfs-3g` and dynamically link Apple's system libraries. This avoids a separate engine dylib search path.

`ac_cv_header_libintl_h=no` deliberately excludes an optional gettext header. On the development Mac, an existing third-party `libintl.h` redirected `setlocale` to `libintl_setlocale`, while upstream did not add the corresponding library. The unmodified tools build instead uses macOS's own locale implementation. Unicode normalization remains enabled through CoreFoundation; Unicode filename and payload behavior must still be tested in the image harness.

The compiler deployment target is macOS 12.0. Compilation with that target does not demonstrate support on macOS 12 or every later version. Each actual OS/architecture/backend combination needs its own runtime verification.

## Validation limits

The compiler target is not a runtime compatibility guarantee. Apple Silicon support is paused. Build success does not demonstrate filesystem integrity, Windows acceptance, safe eject, journal handling, Finder operations, sleep/wake behavior, USB-removal resilience, or crash recovery. Test only disposable images and backed-up spare media under a separately reviewed write policy. Private-machine reports are deliberately excluded from this source staging tree.

## Open-source preparation

Upstream identifies its NTFS drivers, utilities and `libntfs-3g` as **GPL version 2 or later**; the exact source archive includes `COPYING`. The local static tools therefore retain that license rather than inheriting any future Nativol license. `pkgconf`'s short permissive `COPYING` text is preserved with its source and copied into the output notices. The disabled FUSE driver means this tools-only build contains neither macFUSE nor fuse-lite.

Keep the source archive, build scripts, notices, modifications (currently none), and build configuration available as corresponding-source material before redistributing these binaries. The current app package does not automatically bundle them. The owner selected MIT for original Nativol code; third-party license obligations remain separate. The GPL health source and patches are not covered by a blanket MIT grant. Publishing reproducible steps is not a claim of bit-for-bit reproducible binaries: compiler/SDK versions, generated timestamps, and build paths have not been normalized.
